# notedocal 🌙

**Note** + **To-Do** + **Cal**endar — заметки, список дел и календарь в одном приложении,
с поддержкой **григорианского** и **исламского (хиджра)** календарей.

Кроссплатформенное веб-приложение: открывается в любом браузере (телефон, планшет,
компьютер), работает офлайн, данные хранятся прямо на устройстве. Можно «установить»
на телефон как обычное приложение (PWA).

## Возможности

- 📅 **Календарь** — сетка месяца с двойными датами (григорианская + хиджра), сегодняшний
  день и выбранный день подсвечены. На днях с задачами/заметками — цветные точки.
- ✓ **Задачи** — список дел с приоритетами, сроками и отметкой выполнения.
- 📝 **Заметки** — быстрые текстовые заметки с редактированием.
- 🗓 **День** — кликнув по дню в календаре, можно добавить задачи и заметки именно на эту дату.
- 🌗 Светлая и тёмная темы (автоматически по системным настройкам).
- 💾 Данные хранятся в `localStorage` браузера — приложение работает офлайн и
  без регистрации.
- ☁️ **Синхронизация между устройствами** (опционально) — вход через Google,
  и заметки/задачи едины на Windows, Linux и Android. См. раздел
  «[Синхронизация между устройствами](#синхронизация-между-устройствами)».

Хиджра-даты вычисляются встроенным в браузер механизмом `Intl` (календарь
`islamic-umalqura`, Умм аль-Кура) — без внешних библиотек.

## Технологии

## Синхронизация между устройствами

Приложение — это PWA: один и тот же код открывается в браузере на Windows,
Linux и Android. Чтобы данные были **едины** на всех устройствах, подключается
бесплатный Firebase (вход через Google + база Cloud Firestore). Без настройки
приложение продолжает работать как раньше — локально, без входа.

### Как это работает

- Войдя через Google на каждом устройстве, вы получаете единый набор данных.
- Изменения отправляются в облако и приходят на другие устройства почти мгновенно
  (realtime-подписка Firestore).
- Слияние идёт по принципу «последнее изменение побеждает» (по времени правки);
  удаления переносятся через «надгробия», поэтому удалённое на одном устройстве
  исчезает и на других.
- Всё работает офлайн: правки копятся локально и досинхронизируются при сети.

### Настройка

Проект Firebase для этого приложения **уже настроен**, а его публичный веб-конфиг
зашит в [`src/lib/firebaseConfig.ts`](src/lib/firebaseConfig.ts) — поэтому
никаких дополнительных действий для работы синхронизации не требуется: соберите
и задеплойте приложение, нажмите «Войти через Google» — и всё.

Действующие правила Firestore: каждый пользователь видит только свои данные;
календарь наблюдений Tawhiid (`shared/calendar`) читают все, а пишет только
администратор (по email):

```
rules_version = '2';
service cloud.firestore {
  match /databases/{database}/documents {
    // Приватные данные пользователя: сам документ и все подколлекции
    // (users/{uid}/relations/*, в будущем users/{uid}/notes/* и т.п.)
    match /users/{uid}/{document=**} {
      allow read, write: if request.auth != null && request.auth.uid == uid;
    }
    // Календарь Tawhiid: читают все (в т.ч. без входа), пишет только админ
    match /shared/{doc} {
      allow read: if true;
      allow write: if request.auth != null
        && request.auth.token.email == 'ismailovvism@gmail.com'
        && request.auth.token.email_verified == true;
    }
  }
}
```

> Ключи веб-конфига Firebase **не секретны** — они всё равно попадают в собранный
> JS, видимый в браузере. Доступ к данным защищают правила Firestore выше и
> список авторизованных доменов в Firebase Authentication, а не сокрытие ключей.

### Вложения файлов (Firebase Storage)

Файлы, прикреплённые к заметкам и задачам, хранятся в **Firebase Storage**
(в самой записи — только ссылка и метаданные, поэтому лимит документа Firestore
не расходуется). Чтобы вложения заработали:

1. В консоли Firebase откройте **Build → Storage** и нажмите **Get started**
   (может потребоваться тарифный план Blaze — у него есть бесплатный лимит).
2. Задайте правила Storage: каждый пользователь читает и пишет только свои файлы
   (`users/{uid}/files/**`):

```
rules_version = '2';
service firebase.storage {
  match /b/{bucket}/o {
    match /users/{uid}/files/{fileId=**} {
      allow read, write: if request.auth != null && request.auth.uid == uid;
    }
  }
}
```

Пока Storage не включён, кнопка «Прикрепить файл» появится только после входа, а
загрузка вернёт ошибку доступа. Заметки, задачи и остальное продолжают работать
без Storage.

### Документы и пароли (карточки персон)

В «Справочнике» персоны (в т.ч. вы и члены семьи) хранят документы и пароли как
дочерние заметки:

- **Документы** (`document`): вид, номер, срок действия и сканы/фото
  (во вложениях). Приватность — на уровне аккаунта (правила Firestore).
- **Пароли** (`credential`): шифруются **сквозным (E2E) мастер-паролем**.
  Ключ выводится в браузере (PBKDF2 + AES-GCM, Web Crypto), в облако уходит
  только шифртекст. Мастер-пароль **нигде не хранится** и не восстанавливается —
  если забыть, зашифрованные пароли расшифровать нельзя. Соль и верификатор
  лежат в служебной заметке `vault-meta` и синхронизируются, чтобы разблокировать
  хранилище тем же мастер-паролем на другом устройстве.

### Источники хиджра-даты и роль администратора

Дата по хиджре для каждого дня выбирается по приоритету источников:

1. **Календарь Tawhiid** (наблюдения администратора, `shared/calendar`) — если включён.
2. **Личные наблюдения пользователя** (`users/{uid}.sightings`).
3. **Расчётный календарь** Умм аль-Кура (`Intl`) — помечается как
   предположительный (знак «≈»).

Администратор определяется по email (`ADMIN_EMAIL` в
[`src/lib/firebase.ts`](src/lib/firebase.ts)). Его наблюдения сохраняются в общий
документ и видны всем — в том числе пользователям без входа. Обычный
пользователь может отключить календарь Tawhiid переключателем и опираться
только на свои наблюдения и расчёт. Название бренда задаётся `CALENDAR_BRAND`.

### Свой проект Firebase (необязательно)

Если хотите подключить **другой** проект Firebase (например, отдельный для
разработки), не меняя код:

1. Создайте проект на <https://console.firebase.google.com>, добавьте
   Web-приложение, включите провайдер **Google** в Authentication и в
   **Authorized domains** добавьте свой домен и `localhost`.
2. Создайте базу **Firestore** и задайте правила, как выше.
3. Локально: `cp .env.example .env` и впишите ключи нового проекта — переменные
   `VITE_FIREBASE_*` перекрывают значения по умолчанию.
4. Для GitHub Pages: те же ключи добавьте в **Settings → Secrets and variables →
   Actions → вкладка Variables**; workflow деплоя подставит их при сборке.

## Секретарь: дела из командной строки

`scripts/secretary.mjs` — CLI, который пишет и читает те же данные, что и
приложение. Задача, добавленная в терминале, появляется на телефоне почти
мгновенно: подписка в [`src/lib/sync.ts`](src/lib/sync.ts) уже слушает эти
документы, менять в приложении ничего не нужно.

Нужен, когда вводить руками в интерфейс долго или неудобно — проще продиктовать
делá текстом.

```bash
npm run secretary -- task add "Купить фильтр для воды" --date завтра
npm run secretary -- task add "Уточнить цены" --date чт --list "Смета"
npm run secretary -- task list --open
npm run secretary -- task done "фильтр"

npm run secretary -- event add "Созвон с Русланом" --date чт --start 15:00 --end 16:00
npm run secretary -- note add "Идея" --body "Текст заметки"

npm run secretary -- agenda --days 7      # сводка: события + открытые задачи
npm run secretary -- help                 # все команды
```

Даты понимаются по-человечески: `сегодня`, `завтра`, `послезавтра`, `пн`…`вс`
(ближайший будущий), `+3`, `14.08`, `2026-08-14`, `none` (без даты). Флаг
`--json` у любой команды даёт машинный вывод — удобно для скриптов и агентов.

Пачку записей можно закинуть одним вызовом:

```bash
npm run secretary -- batch дела.json
# [{"kind":"task","text":"Смета","date":"ср"},
#  {"kind":"event","title":"Созвон","date":"чт","start":"15:00"}]
```

### Настройка (один раз)

1. **Ключ доступа.** Firebase Console → **Project settings → Service accounts →
   Generate new private key**. Сохранить как `service-account.json` в корне
   проекта.

   > Это **настоящий секрет**, в отличие от публичного веб-конфига Firebase: он
   > даёт полный доступ к базе в обход правил Firestore. Файл уже в
   > `.gitignore` — не коммитить и никуда не выкладывать.

2. **Чьи данные править.** `cp .env.example .env` и вписать `SECRETARY_EMAIL` —
   тот же аккаунт Google, которым выполнен вход в приложении. Посмотреть
   доступные аккаунты:

   ```bash
   npm run secretary -- who
   ```

### Запуск в облачной среде (веб, телефон, CI)

В облачной сессии есть только то, что лежит в git, а `service-account.json` и
`.env` туда намеренно не попадают. Поэтому ключ можно передать переменной
окружения — тогда файлы не нужны:

| переменная | значение |
| --- | --- |
| `SECRETARY_KEY` | содержимое `service-account.json` — как есть или в base64 |
| `SECRETARY_EMAIL` | аккаунт, чьи дела правим |

Получить ключ одной строкой для вставки в секреты среды:

```bash
base64 -w0 service-account.json
```

Base64 — потому что в приватном ключе есть переносы строк, а поля секретов
обычно однострочные. Скрипт принимает оба вида: строка, начинающаяся с `{`,
читается как JSON, остальное декодируется из base64.

> Ключ даёт полный доступ к базе мимо правил Firestore. Хранить его стоит
> только в секретах среды, не в переменных, которые попадают в логи или в
> историю команд.

Проверка, что связь есть:

```bash
npm run secretary -- who
```

### Как это устроено

Скрипт повторяет модель данных из `sync.ts`: задачи — это пункты чек-листов в
поле `checklists` документа `users/{uid}`, события — в `events`, заметки — в
подколлекции `users/{uid}/notes`. Задача без явного `--list` попадает в общий
список без названия — ровно как кнопка «быстрая задача» в приложении
(см. `ChecklistBoard.addQuickTask`).

Запись идёт транзакцией, поэтому одновременная правка с телефона ничего не
затирает. Логика разбора дат и дерева задач покрыта тестами:

```bash
npm test
```
